# 2026-09-13

## Tooling: pgAdmin added to the local Compose stack

No GUI existed for poking at the local Postgres without reaching for `psql`. Added a `pgadmin`
service to `local/docker-compose.yml` and a `make pgadmin` target. See [[running-locally]].

- **Gated behind a new `tools` Compose profile**, mirroring the existing `offline` pattern used
  for Ollama — plain `make up` is unaffected; `make pgadmin` starts Postgres (if not already up)
  plus pgAdmin at `http://localhost:5050`. `down` / `nuke` extended with `--profile tools` so the
  container (and, on `nuke`, its `pgadmin-data` volume) don't need a separate cleanup path.
- **Auto-registers the local connection** via a mounted `local/pgadmin/servers.json` (host
  `postgres`, matching how `cassandra-init` already reaches `cassandra` by service name in the same
  file) — the `demo_chat` server shows up pre-filled in pgAdmin's tree on first login; the Postgres
  password is still typed once (or saved into the `pgadmin-data` volume via pgAdmin's own "Save
  Password" checkbox).
- Login for pgAdmin itself: `demo_chat@example.com` / `demo_chat`, same throwaway-credential style
  as the rest of the local stack.
