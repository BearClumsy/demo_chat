## Data layer
- Configured Postgres/Cassandra/Qdrant/Kafka connection properties in `application.properties`, plus a
  tuned HikariCP pool for Postgres.
- Added the first Flyway migration (`V1__create_users_table.sql`): `demo_chat` schema + `users` table
  (UUID PK, unique email/login).
- Found and fixed a real bug: Postgres's `"$user", public` search_path silently resolved to the
  `demo_chat` schema once it existed (DB role is also named `demo_chat`), desyncing Flyway's history
  table from the schema it manages. Fixed by pinning `spring.flyway.schemas=demo_chat`.
- Resolved a Spring AI Bedrock startup failure (ambiguous `EmbeddingModel` bean between Cohere and
  Titan) by setting `spring.ai.model.embedding=bedrock-titan`.

## API
- Built out `com.example.demo_chat.user` (package-by-feature): `User` entity, `UserRepository`,
  `UserService`, `UserResponse`.
- `GET /api/users/{id}` — reactive WebFlux endpoint, blocking JPA bridged via
  `Schedulers.boundedElastic()`, 200/404, automatic 400 on a malformed UUID.
- `POST /api/users` — validated `CreateUserRequest` (`jakarta.validation`, size limits matching DB
  column widths), BCrypt password hashing (`spring-security-crypto`), 201 with `Location` header, 409
  on duplicate email/login.
- Moved `UserController` into `com.example.demo_chat.user` for a consistent package-by-feature layout.
- Added Javadoc across the whole `user` package.
- All endpoints exercised end-to-end against the real local Postgres container (not just unit tests).
