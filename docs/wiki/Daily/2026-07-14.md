# 2026-07-14

## API — RAG pipeline
- Implemented the Phase 1 RAG pipeline end to end: normalize → retrieve → classify → scope-check →
  slot-fill → generate, in a new flat `com.example.demo_chat.rag` package, orchestrated by
  `ChatPipelineService`. Chose flat package-by-feature over the original design notes'
  `service.<layer>.ClassName` naming, to match the convention already established by `chat/`/`user/`
  (see [[backend|backend.md]]'s Rationale section).
- Added `POST /api/chats/{chatId}/messages`: `SendMessageRequest` takes `userId` from the authenticated
  principal rather than the request body (tighter than the existing `MessageRequest`, which is only used
  for a chat's initial message at creation time). Added `ChatService.getChatForParticipant()` for the
  404 (no such chat) / 403 (not a participant) split.
- 4 intents (`refund_status`, `order_status`, `change_shipping_address`, `password_reset`) in
  `knowledge-base/intents/*.json`, loaded at startup by `IntentDefinitionRegistry` and pushed into the
  Qdrant `support_kb` collection by `KnowledgeBaseIndexer` (idempotent — document id = intent id).
- Deliberate Phase-1 simplifications (see [[rag-pipeline|rag-pipeline.md]]): no separate Spring AI
  `ChatMemory` (reused `ChatHistory`, which already logs every turn); `DialogueState` holds only
  status/intent/slots, not a duplicated history list; slot filling takes the next raw message verbatim
  instead of a 4th LLM call per turn; knowledge-base reindex runs on app startup instead of a CI job;
  output guardrail deferred to Phase 2.

## Dependencies — Bedrock Converse starter
- Root-caused a `NoSuchBeanDefinitionException` for `ChatModel`: `spring-ai-starter-model-bedrock` only
  autoconfigures the Titan/Cohere **embedding** models — the Bedrock **Converse** chat model moved to a
  separate `spring-ai-starter-model-bedrock-converse` artifact in Spring AI 2.0.0. Not a broken/missing
  package as first suspected; confirmed by pulling the real `spring-ai-bom:2.0.0` POM from Maven Central
  and finding both starters listed as siblings. Added the missing starter to `build.gradle`.
- Verified the fix by observing an *expected* `403` from a real Bedrock call using placeholder AWS
  credentials (`AWS_ACCESS_KEY_ID=test`) — proves the entire bean graph (`ChatModel` → `ChatClient` →
  every pipeline service → `ChatController`) and the network path to AWS are wired correctly. A full
  dialogue against real AWS credentials hasn't been run yet.

## Infrastructure & tooling
- Local Cassandra container was being OOM-killed (exit 137) — the Docker VM here only has ~1.9 GB total,
  not enough for Cassandra's auto-sized heap alongside Postgres/Qdrant/Kafka. Fixed with explicit
  `MAX_HEAP_SIZE: 512M` / `HEAP_NEWSIZE: 128M` on the `cassandra` service in `docker-compose.yml`.
- Added `spring.cassandra.schema-action=create-if-not-exists` — nothing was creating `chat_history`/
  `chat_message` (pre-existing, from yesterday) or the new `dialogue_state` table before this; a gap in
  the existing chat feature, not just the new one.
