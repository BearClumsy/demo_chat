# 2026-08-12

## Root Makefile
- Added a root `Makefile` as a single entry point for the repo. The motivation was discoverability,
  not build capability: the commands were already documented, but split across module-scoped Gradle
  tasks, npm that only runs from `modules/client` (that module still isn't in the Gradle build), a
  compose file buried at `modules/server/src/main/resources/local/`, and two `docker build`
  invocations with *different* contexts — the server image builds from the repo root because the
  Gradle wrapper lives there, the client from `modules/client`. That asymmetry was the easiest thing
  to get wrong by hand, so it's now encoded once.
- Deliberately a thin alias layer: every recipe shells out to `./gradlew`, `npm`, `docker` or `node`.
  No build logic is duplicated into make, so Gradle stays the source of truth and there's nothing to
  keep in sync semantically — only the command list.
- Written against the GNU make **3.81** that ships with macOS, so no `.ONESHELL` and no
  `.RECIPEPREFIX`. Consequence: client recipes are single `cd $(CLIENT_DIR) && …` lines, since each
  recipe line otherwise runs in its own shell.
- `make ci` mirrors the checks in the three workflows from [[github-actions]] but deliberately omits
  the container image builds those workflows also do — they're slow locally and rarely what you want
  from a pre-push check. `make ci docker` is the full-parity form.
- Verification was partial: `help`, the `-n` dry runs, `validate-intents`, `fmt-check`, `client-lint`
  and `client-build` all ran green, but `build`/`test`/`up`/`docker` were left unrun because the
  Docker daemon wasn't up on this machine. Worth re-running once Docker is available.
- Added a `make help` pointer to both `CLAUDE.md` and `README.md` under their Commands sections, with
  the underlying commands left in place — the Makefile is a shortcut, not a replacement, and both
  docs now say new commands go in both places.
