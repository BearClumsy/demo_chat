# 2026-08-31

## Phase 3b (no-AWS slice): Terraform skeleton + lint CI

Branch `phase-3b-terraform-skeleton` (off `main`). Delivers the part of [[roadmap]] Phase 3b that
needs no AWS account: the Terraform *code*, CI-linted but never applied.

- **`infra/terraform/`** — first IaC in the repo. `modules/{vpc, alb, ecs-service, rds-postgres,
  keyspaces, qdrant-ec2, msk, bedrock-iam}` + duplicated `envs/{staging, prod}` roots (same
  rationale as the duplicated `application-{staging,prod}.properties`). Layout follows the target
  in [[infrastructure]]; additions vs. that target: an `msk/` module (the `KAFKA_BOOTSTRAP_SERVERS`
  contract needs it); omissions: `s3-cloudfront/` and the `cassandra-ec2/` alternative.
- Each env's `main.tf` builds a `plaintext_env` map and `outputs.tf` exposes it as `container_env`
  — every key must line up with a property in `application-{staging,prod}.properties`. Secrets
  (`POSTGRES_PASSWORD`, `CASSANDRA_PASSWORD`, `QDRANT_API_KEY`) stay out of it, injected from
  Secrets Manager via `task_secret_arns`. `POSTGRES_SCHEMA` is deliberately not a variable — the
  app's Flyway V1 hardcodes `demo_chat`.
- Data-tier ingress (`rds-postgres`, `qdrant-ec2`, `msk`) is by app-subnet **CIDR**, not a
  security-group reference — referencing the ECS task SG would make a module dependency cycle with
  the container-env wiring. Noted as a TODO to tighten.
- `backend "s3"` blocks in `envs/*/versions.tf` are commented out until the state bucket + lock
  table exist; CI runs `terraform init -backend=false`.
- Keyspaces: only `open_chats_by_bucket` is modelled. `chat_history` / `dialogue_state` use the
  `ChatMessage` UDT and a wider column set — their source of truth is the JPA entities / CQL, still
  to be ported before an apply.

- **`.github/workflows/terraform-lint.yml`** — own lightweight lane (like `knowledge-base-lint`),
  path-filtered to `infra/**`. Runs `terraform fmt -check`, `validate` on both env roots with
  `init -backend=false`, and `tflint --recursive`. **No AWS credentials configured** — none of
  those steps call AWS.
- **`Makefile`** — new `tf-lint` / `tf-fmt` targets (auto-detect `terraform` or `tofu`). Not added
  to `make ci` (which mirrors only the code/KB workflows).
- `.gitignore` — Terraform artifacts; `.terraform.lock.hcl` intentionally not committed yet (CI
  uses HashiCorp Terraform, a lock generated by OpenTofu pins `registry.opentofu.org` sources).

Verified locally with OpenTofu 1.9.0 + tflint 0.53.0 (aws ruleset 0.35.0): `fmt -check`,
`validate` (staging + prod), and `tflint --recursive` all pass; `make tf-lint` exits 0.

Still needs an account (unchanged): `terraform apply`, the state backend, real AMI/cert/secret
values, the full Keyspaces schemas, and the `deploy-staging` / ECR / OIDC work. The KB-reindex CI
job (chosen shape: mechanism test only) and `deploy-staging.yml` were scoped out of this branch.

Docs updated: [[roadmap]] (Phase 3b Terraform bullet → `[~]`), [[infrastructure]] (status +
skeleton tree), [[github-actions]] (`terraform-lint` added to the implemented list), `CLAUDE.md`
(new Infrastructure subsection under Commands).

## Code review of the skeleton — follow-ups before an apply

`/code-review` over the branch diff. Lint is green, but eight things to fix before this can meet a
real account (ranked):

- **`CASSANDRA_USER` missing from `plaintext_env`** (`envs/{staging,prod}/main.tf`). The properties
  have `spring.cassandra.username=${CASSANDRA_USER}` with no default and it's nowhere in `infra/`
  — nor in the `task_secret_arns` contract. Container would fail startup on the unresolved
  placeholder. Contradicts the "every key lines up with `application-*.properties`" claim above and
  the README env-var table.
- **No `health_check_grace_period_seconds` on the ECS service** (`modules/ecs-service/main.tf`).
  Container health check already sets `startPeriod=90` for the Flyway + Cassandra/Qdrant/Bedrock
  boot; with a `load_balancer` block and no grace period the ALB fails the target at 3×30s and ECS
  kills/replaces the task before it's ready — first deploy never reaches steady state.
- **`tflint --init` has no `GITHUB_TOKEN`** (`.github/workflows/terraform-lint.yml`). Fetching the
  AWS ruleset hits the 60/hr anonymous GitHub API limit on shared runners → intermittent 403s.
  Add `GITHUB_TOKEN: ${{ github.token }}` to the init step.
- **MSK plaintext leftovers** (`modules/msk/main.tf`). `client_broker = "TLS"` disables the 9092
  listener, so the `9092` ingress rule is dead and `output "bootstrap_brokers_plaintext"` always
  resolves to `""` — a silent misconfig for anything wiring `KAFKA_BOOTSTRAP_SERVERS` to it.
- **Static `final_snapshot_identifier`** (`modules/rds-postgres/main.tf`). `skip_final_snapshot =
  false` + a fixed name → a second destroy after a recreate fails `DBSnapshotAlreadyExists`.
  Suffix with a timestamp/`random_id`.
- **Subnet CIDR lists not validated against AZ count** (`modules/vpc/main.tf`). `count =
  length(var.azs)` indexes three separate `*_subnet_cidrs` lists; adding an AZ without matching
  entries gives an opaque "index out of range". Add a `validation` block or derive with
  `cidrsubnet()`.
- **`Makefile` `TF_BIN` uses recursive `=`** — the `$(shell command -v …)` probe re-runs on every
  reference (6× per `tf-lint`). Adjacent `TF_DIR` is `:=`; make `TF_BIN` `:=` too.
- **Bedrock policy scoped to a single-region foundation-model ARN** (`modules/bedrock-iam/main.tf`).
  Region default is `eu-central-1`, where Anthropic access generally needs a cross-region
  inference-profile ARN (`eu.anthropic.claude-3-5-haiku-…`) plus the underlying `foundation-model/*`
  ARNs — `InvokeModel` would return `AccessDeniedException` against a real account.

## Tooling: graphify graph rebuilt for the new infra

- Full `/graphify .` rebuild (not `--update`) now that `infra/terraform/` exists — 179 files, graph
  went 1079 → 960 nodes (the on-disk `graph.json` predated this branch; the shrink-guard was
  overridden after confirming all 8 extraction chunks landed).
- **Durable gotcha for future runs:** `.tf` / `.hcl` / `.sql` files produce **zero AST nodes** —
  `tree_sitter_hcl` / `tree_sitter_sql` aren't installed. Structural Terraform coverage (module
  composition, per-module AWS resources, CIDR/secret wiring) currently comes only from the semantic
  pass. Install `graphifyy[terraform]` + `graphifyy[sql]` before the next rebuild for real AST edges.
- New graph carves the infra into its own communities — "Terraform VPC Module (three-tier subnets)",
  "ECS Service & Infra Wiring Rationale", "Terraform Env Roots & ALB/Bedrock Modules" — and surfaces
  a cross-boundary edge from the `bedrock-iam` module to the `container_env ↔ application-*.properties`
  contract captured in this note, i.e. the same contract the `CASSANDRA_USER` finding above is about.
