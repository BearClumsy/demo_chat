# 2026-08-20

## Wiki maintenance: User feature page gap

- Routine review of [[User]] found its Decisions and Related Code sections predated the 2026-08-13
  Flyway work — still describing Postgres migrations as app-only, with no mention of the standalone
  `flywayMigrate`/`flywayInfo` tasks or the schema-override fix landed that day.
- Backfilled into Decisions: the standalone tasks exist so the `users` schema can be migrated without
  booting the app (CI, a fresh database, ad-hoc ops); `flywayClean` is deliberately disabled
  (`cleanDisabled = true`); `schemas` is overridable via `-Pflyway.schemas`/`FLYWAY_SCHEMAS` rather than
  hardcoded, matching the existing `url`/`user`/`password` override pattern. That override matters
  because a hardcoded value would silently build a second, divergent `flyway_schema_history` table
  against staging/prod, which resolve `spring.flyway.schemas` from `${POSTGRES_SCHEMA}` at runtime —
  Boot's startup migration and the standalone tasks have to agree on `schemas` or each re-runs the
  other's migrations.
- Backfilled into Related Code: `modules/server/build.gradle`'s `buildscript {}`/`flyway {}` blocks and
  the `Makefile`'s `migrate`/`migrate-info` targets.
- Docs-only — no code changed today. The gap and backfill are also recorded in [[User]]'s own Source
  Log under a 2026-08-20 entry.
